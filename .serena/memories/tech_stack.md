# Tech stack

- Python 3.13+ (ruff `target-version = "py313"`, CI matrix 3.13-3.14). Standard library only at runtime (argparse, subprocess, json, re, ipaddress, hashlib, collections.Counter, datetime). Not a package: `pyproject.toml` holds only ruff and coverage settings, and `requirements.txt` only documents that there are no runtime deps.
- `analyze.py`: stdlib `urllib.request` + `json` against the Ollama native API (`/api/chat`, structured output via a `format` JSON schema). The server was Ollama 0.40.2 on 2026-10-21.
- basedpyright (strict) floods both scripts with missing-annotation warnings and spurious `LiteralString`/`builtins.str` "errors". The project deliberately has no type hints, so only real errors matter.
- External runtime dependency: `journalctl` binary (systemd), invoked as `journalctl --output=json --all --no-pager --quiet [host args] (--since=... | --after-cursor=...)`. `--all` is required, otherwise fields over 4096 bytes (coredump traces) come out as null.
- Target host: `palvelin` (openSUSE Tumbleweed), run with sudo. Dev machine differs (Fedora); never run against real journals.
- Tests: stdlib unittest suites in `tests/` (commands and harnesses: `mem:suggested_commands`). `pytest.ini` (`testpaths = tests`, `pythonpath = .`) lets pytest collect them unchanged.
- Dev tools (never runtime deps): `requirements-dev.txt` (`pytest>=9.1.1`, `pytest-cov>=7.1`, `ruff==0.17.1`) plus the hashed universal lock `requirements-dev.lock`. After editing requirements-dev.txt, regenerate it with `uv pip compile --universal --generate-hashes --no-header --python-version 3.13 --upgrade --exclude-newer "7 days" requirements-dev.txt -o requirements-dev.lock`. `--upgrade` also refreshes the indirect deps (coverage, pluggy, pygments, packaging, iniconfig and others), which Dependabot never sees; without it every existing pin is kept. `--exclude-newer "7 days"` matches the Dependabot cooldown. Because of both flags the output depends on the run date, so it reproduces the committed lock byte for byte only while nothing newer has been released.
- CI (`.github/workflows/ci.yml`; runs on push to main, PRs and manual dispatch):
  - Ruff job (`astral-sh/ruff-action`, version read from `requirements-dev.txt`): `ruff check --output-format=github` and `ruff format --check --diff`.
  - Test job on Python 3.13-3.14: installs the lock with `--require-hashes --only-binary :all:`, checks with `pip install --no-index --only-binary :all: --dry-run -r requirements-dev.txt` that the installed lock satisfies requirements-dev.txt (fails on a Dependabot pip PR until the lock is regenerated), and runs `python -m pytest --cov --cov-report=xml`. Coverage config in `pyproject.toml`: branch, `omit = tests/*`, and `patch = ["subprocess"]` so that the logfilter.py runs started by the E2E tests are measured.
  - SonarQube Cloud job (`sonar-project.properties`, `SONAR_TOKEN` secret; Automatic Analysis must stay disabled in SonarQube Cloud) scans using the 3.14 `coverage.xml`.
  - OSV-Scanner workflow (`.github/workflows/osv-scanner.yml`; push to main, PRs, merge_group, weekly schedule): calls `google/osv-scanner-action` reusable workflows (`osv-scanner-reusable.yml` and `osv-scanner-reusable-pr.yml`) with `--lockfile=requirements.txt:requirements-dev.lock` (scanning `requirements-dev.txt` without `--no-resolve` would resolve unpinned lower bounds via deps.dev and flag old transitive versions not in the lock).
  - Taint findings on CLI arguments are False Positive by policy: `mem:analyze`.
  - Every `uses:` is pinned to a full commit SHA plus a `# vX.Y.Z` comment, and every checkout has `persist-credentials: false`. `uvx zizmor --offline .github/` is clean (even `--persona=pedantic`); keep it that way.
- Dependabot (`.github/dependabot.yml`): weekly, 7-day cooldown; github-actions and pip, each grouped into one PR (one lock regeneration per week, and no lock conflicts between separate pip PRs). The pip updater only edits `requirements-dev.txt` and cannot touch `requirements-dev.lock`, so its PRs need the lock regenerated (command above) and pushed before merging; otherwise the test job would keep the old tool versions while the Ruff job uses the new ruff. The test job's lock check fails until the lock is regenerated. `SONAR_TOKEN` is also stored as a Dependabot secret, because Dependabot-triggered runs get no Actions secrets and the SonarQube job would fail without it.
- Serena LS: `python_basedpyright` (set in `.serena/project.yml`); Serena launches it via `uvx -p 3.13 --from basedpyright==<pinned>`, so uv needs a Python 3.13 interpreter available.
